# checketop — генерация банковских чеков (PDF)

## Цель проекта

Telegram-бот, который по запросу пользователя генерирует PDF-чеки переводов,
проходящие автоматическую проверку как оригинальные («зелёные»).

Проверка сверяет не картинку, а внутреннюю структуру PDF: метаданные,
шрифтовые сабсеты, контент-стримы, способ сохранения файла. Поэтому чек
должен быть неотличим от настоящего не только визуально, но и по байтам.

**Начинаем с Яндекса.** Остальные банки — после того, как Яндекс станет зелёным.

## Банки

| Папка | Банк / тип чека | Статус |
|---|---|---|
| `banks/yandex/` | Яндекс (перевод) | ✅ движок готов (podlinno 45/45, 04.11.2026), бот подключён |
| `banks/rocket/` | Рокетбанк (СБП + карта) | 🟡 патчер есть, статус проверки уточнить в `BANK.md` |
| `banks/vtb/` | ВТБ (карта) | 🟡 генератор перенесён в `banks/vtb/`, статус уточнить |
| `banks/other_sbp/` | СБП из `Check.pdf` | ⚪ не начат |

Подробности по каждому банку — в его `banks/<bank>/BANK.md`.

## Главное правило

> **PDF не перерисовывается заново, а патчится настоящий донор.**

- Берём настоящий чек (донор) и меняем в нём только значения полей:
  сумму, дату, получателя, номер операции и т.д.
- Всё остальное — шрифты, сабсеты, объекты, порядок байтов, способ
  сохранения — остаётся как в оригинале.
- Генерация «с чистого листа» (новый документ, перерисовка текста и картинок)
  проверку не проходит, даже если визуально чек идентичен.

Следствие: `rebuild_pdf.py` — устаревший подход для Яндекса (пересоздаёт PDF
заново), новый код так не делаем. Для Рокета эталон — `patch_rocket.py`:
донор сохраняется байт-в-байт, правки пишутся инкрементальным апдейтом.

## Порядок работы по чатам

Работаем отдельными чатами, у каждого — одна задача. Чат не трогает чужие зоны.

| Чат | Задача |
|---|---|
| `00-инфра-структура-проекта` | Порядок в репозитории: структура папок, `PROJECT.md`, `BANK.md`, git. Генераторы не переписывает. |
| `01-яндекс-…` (следующий) | Яндекс: исследование донора и патчер по образцу Рокета. |
| далее по одному чату на банк | Рокет → ВТБ → СБП, в порядке готовности. |
| бот — отдельным чатом | Telegram-бот подключает готовые генераторы. В этом чате бота не трогаем. |

Правила для каждого чата:

1. Перед работой прочитай этот файл и `BANK.md` своего банка.
2. Не меняй логику чужих генераторов и не удаляй PDF-доноры.
3. Результаты генераций — в `out/` (в .gitignore), доноры и код — в git.
4. Итог чата фиксируй в `BANK.md` своего банка: что работает, что не
   проходит проверку, гипотезы.

## Telegram-бот (Яндекс + Рокет)

Бот — отдельный слой поверх готового движка: он ведёт диалог, валидирует
ввод и вызывает движок. Логики работы с PDF в боте нет и не должно быть.

### Выбор фреймворка: python-telegram-bot

Выбран **python-telegram-bot** (`bot/requirements.txt`: `>=22,<23`;
в текущем окружении уже установлен 22.7, aiogram не установлен — лишняя
зависимость не нужна). Решающий аргумент — встроенный `ConversationHandler`:
конечный автомат диалога из коробки, а состояние каждого диалога хранится
в `context.user_data` с привязкой к паре (chat, user). Своя FSM на
глобальных словарях не пишется в принципе, поэтому состояния разных
пользователей не могут перемешаться. aiogram даёт то же через свою FSM,
но потребовал бы новый стек зависимостей ради одной задачи бота.

### Контракт движка

Бот лениво (в момент генерации, не при старте) загружает
`banks/yandex/engine.py` и вызывает:

```python
generate_yandex(
    amount="10 000,00 ₽",                    # канонический вид из parse_amount
    operation_dt=datetime(..., tzinfo=MSK),  # МСК, tz-aware
    sender_name="Иванов Иван Иванович",
    sender_phone="+7 900 351-70-80",         # нормализованный parse_phone
    recipient_name="Петрова Анна Ивановна",
    recipient_phone="+7 963 297-20-08",
    recipient_bank="Сбербанк",
    output_path="/path/to/out.pdf",
    donor_path="/tmp/.../template.pdf",   # только режим «с шаблоном», см. ниже
) -> str | Path | bytes | None   # путь к PDF, bytes PDF или None (файл в output_path)
```

> **Статус на 04.11.2026: `banks/yandex/engine.py` готов** и вызывает
> существующий патчер (`patch_yandex.py` + `yandex_receipt.py` +
> `yandex_font.py`, логика патчера не менялась) в замороженной
> конфигурации, прошедшей `@podlinno_bot` на 45/45: natural-save,
> точные сабсеты, свежие теги, CreationDate — момент генерации,
> серийный токен СБП наследуется от донора, хвост `0011881102`,
> комиссия и сообщение всегда «—», имя выхода — `<uuid4>.pdf`.
> Путь к движку при необходимости переопределяется переменной
> окружения `YANDEX_ENGINE_PATH` (используется в тестах).
>
> **Пул и одноразовые токены.** Шаблоны лежат в
> `banks/yandex/donors/` (настоящие чеки Яндекса из корня проекта;
> ноябрьские оригиналы владелец может докладывать туда же). Реестр
> потраченных серийных токенов СБП (поз. 12–22) —
> `banks/yandex/donors/spent_tokens.json`: файл состояния, переживает
> перезапуск бота (путь можно переопределить `YANDEX_TOKEN_REGISTRY`).
> На каждую генерацию движок выбирает самого свежего донора, чей
> токен ещё не потрачен и который набирает все введённые строки
> своими глифами без доращивания шрифта, помечает токен потраченным
> **до** генерации и назад его не возвращает даже при ошибке.
> Засеяны потраченными токены 04.11.2026: `6381I…` (c0787b9b),
> `90626…` (48a8181b), `3380O…` (02e390b1), `1720E…` (6523d7c5),
> `9446L…` (390ab9c7); чистый донор aea36931 (токен `33340H…`) не
> засеян — в генерациях он не участвовал, его PDF владелец может
> положить в пул вручную (из `~/Downloads` у бота доступа туда нет).
> Если свободных токенов не осталось или буква вне покрытия глифов —
> движок честно отказывает и просит новый настоящий чек Яндекса
> (свежий перевод + скачанная квитанция в `banks/yandex/donors/`),
> а не переиспользует токен и не выдумывает серийник.

### Сценарий Яндекса (паритет с Рокетом)

`/start` → [Яндекс чек] → **[Чек] / [Выписка]**.

**Выписка Яндекса (подключена 05.11.2026).** Бот лениво, только в
момент генерации, вызывает готовый `generate_yandex_statement(...)`
из `banks/yandex/statement.py` (путь переопределяется
`YANDEX_STATEMENT_PATH`), `generated_at` — текущий момент МСК, имя
файла — `<uuid4>.pdf`. Сценарий: период одной строкой
`03.11.2026–05.11.2026` → дата выдачи [Сегодня]/[Ввести дату] →
держатель (ФИО, дата рождения, паспорт — бот форматирует
`4510 123456`; держатель запоминается в `mem_yandex_statement_holder`
и предлагается кнопкой) → договор (дата [Как начало периода]/[Ввести
дату], номер [Сгенерировать автоматически]/[Ввести свой], формат
своего — «Э»+17 цифр) → входящий остаток с копейками → редактор
операций → сводка → генерация. Редактор операций: [Добавить
операцию]/[Без операций], после добавления — список с приходом/
расходом и [Добавить ещё]/[Удалить операцию] (выбор номера)/[Готово
к сводке]; шаблоны [Входящий перевод СБП]/[Исходящий перевод СБП]
(контрагент: ФИО → телефон → банк кнопками как в чеке → дата-время →
сумма; описание бот собирает сам как в настоящей выписке, имя — в
виде «Имя Отчество Ф.», знак ставит по виду операции) и [Своё
описание] ([Приход]/[Расход] → описание → дата-время → сумма).
Дата-время: [Сейчас] только если момент внутри периода, ввод
`04.11.2026 12:40` или только время, если дата понятна из периода;
операция вне периода не принимается. Несколько операций можно
прислать одним сообщением построчно:
`04.11.2026 12:40 | описание | -250,00`. Дата обработки отдельно не
спрашивается (движок ставит дату операции), колонка «Карта» в
интерфейсе не предлагается, продукт и валюта не выбираются.
Сводка: период, выдача, держатель/рождение/паспорт, договор,
остатки и итоги (исходящий = входящий + приход − расход, как в
движке), список операций; каждое поле правится из сводки с
возвратом в сводку, операции — через тот же редактор. Ошибки
движка не роняют бота: короткое «Не получилось: …» (буква вне пула
глифов — изменить имя/описание или владельцу нужна новая настоящая
выписка/чек в пул; не влезает в одну страницу — меньше операций или
короче описания; нет донора выписки — вопрос к владельцу),
traceback в `logs/bot_errors.log`, возврат в сводку. Одноразовых
токенов и реестра у выписки нет.

**Чек.** `/start` → [Яндекс чек] → [Чек] → шаг **«Как создать чек?»** с кнопками
[без PDF] / [с PDF] (рядами по две, плюс [Назад]/[Отмена]).
Диалог Яндекса — «чистый чат» без эффекта удаления: после ответа
пользователя бот удаляет его сообщение, а своё сообщение с вопросом
не удаляет, а редактирует на месте в следующий вопрос — сообщение
просто превращается в следующее, чат не катится вниз; в чате
остаются актуальный вопрос/сводка и готовый документ с чеком:

- **без PDF** (обычное создание) — сценарий ниже без изменений: движок сам берёт
  донора из пула `banks/yandex/donors/` с реестром одноразовых токенов.
  Если свободных доноров актуальной эпохи не осталось и движок честно
  отказывает («нет свободного токена…»), бот не падает и не уходит в
  сводку, а понятным текстом говорит, что нужен свежий настоящий чек
  Яндекса за последние дни, и возвращает к выбору режима.
- **с PDF** (создание с шаблоном) — пользователь присылает PDF настоящей
  квитанции Яндекс Банка. Бот сохраняет её во временную папку
  (системный temp, `checketop_yandex_templates/tpl_*`, путь — только
  в `user_data` этой пары chat+user) и проверяет существующим парсером
  движка (`yandex_receipt.Receipt`): квитанция парсится, есть СБП-ID
  из 32 символов, сообщение отправителя — «—». Невалидный файл —
  понятный отказ, traceback в `logs/bot_errors.log`, возврат к выбору
  режима. Валидный — подтверждение «Шаблон принят» с датой/временем
  операции и суммой донора, дальше тот же сценарий ниже, а в движок
  шаблон уходит существующим параметром `donor_path`. Если токен
  шаблона уже есть в `spent_tokens.json` — предупреждение «этот
  шаблон уже использовался, проверяющий может пометить чек как
  повтор» с кнопками [Всё равно создать]/[Отмена]; если СБП-хвост
  шаблона не равен актуальному `0011881102` — предупреждение, что
  номер операции может не пройти проверку, с теми же кнопками.
  Шаблон одноразовый и в пул `donors/` автоматически не попадает:
  временный файл удаляется после генерации, при отмене и по таймауту
  (старше 1 часа — чисткой при следующем входе в Яндекс и проверкой
  перед генерацией). Прочие ошибки движка — как в обычном режиме:
  короткое сообщение и возврат в сводку.

Далее в обоих режимах: получатель: ФИО → телефон (любой формат →
`+7 XXX XXX-XX-XX`) → банк кнопками в написании как в чеке (Сбербанк,
Т-Банк, ВТБ, Альфа-Банк, ПСБ, Озон Банк (Ozon), Wildberries
(Вайлдберриз Банк), Рокетбанк, «Ввести свой») → сумма (как вводит
пользователь, копейки допустимы, формат `17 350,00 ₽`) → отправитель:
ФИО → телефон (задаётся каждый раз; счёт отправителя у Яндекса нет) →
шаг «Время операции»: [Текущее время] (с секундами) / [Изменить
время] (`03.11.2026 14:20` или только `14:20` = сегодня; без секунд
их подставит движок из донора). Как у Рокета: кнопки рядами по две,
на каждом шаге [Назад]/[Отмена] (и `/cancel`), примеры — `<code>`
для копирования нажатием, невалидный ввод не продвигает диалог;
отправитель и последний получатель запоминаются в `user_data`
(`mem_yandex_*`) и предлагаются кнопкой «Оставить как в прошлый
раз». Сводка «Проверь данные» двумя блоками ПОЛУЧАТЕЛЬ/ОТПРАВИТЕЛЬ
(время — выбранное, с секундами движка), правка любого поля из
сводки с возвратом в сводку. По «Сгенерировать» бот вызывает движок
и присылает PDF документом `<uuid4>.pdf` с подписью-сводкой и
кнопками [Ещё чек]/[Главное меню]. Ошибка движка (например «буква
вне пула глифов») — короткое «Не получилось: …» пользователю,
traceback в `logs/bot_errors.log`, бот не падает и возвращает к
сводке для правки; отказ из-за пустого пула актуальной эпохи —
отдельная ветка выше (понятный текст и возврат к выбору режима).

### Рокетбанк в боте (подключён 03.11.2026)

Тот же скрипт `bot/yandex_bot.py` и тот же `ConversationHandler`
(состояние — только `context.user_data` на пару chat+user). Главное меню
`/start`: [Яндекс] [Рокетбанк]; у Рокета — [Перевод по СБП]
[Перевод по номеру карты] [Выписка]. Движки Рокета бот не переписывает
и PDF сам не трогает: импортирует их лениво в момент генерации
(пути при необходимости переопределяются `ROCKET_ENGINE_PATH` /
`ROCKET_STATEMENT_PATH`, как `YANDEX_ENGINE_PATH` у Яндекса) и вызывает:

```python
generate_rocket(amount="10 000 ₽", operation_dt=datetime(..., tzinfo=MSK),  # second=0: секунды унаследует движок
                sender_name=..., sender_phone="+7 ...", recipient_name=...,
                recipient_phone="+7 ...", recipient_bank="Сбербанк",
                sender_account=None,  # или 20 цифр строкой
                output_path=...)      # banks/rocket/engine.py
generate_rocket_card(amount=..., operation_dt=..., sender_name=...,
                     recipient_card="2200 **** **** 9515",
                     recipient_bank="Сбербанк",  # None = ВБ Банк, без блока банка
                     sender_account=None, output_path=...)
generate_rocket_statement(period_start=date(...), period_end=date(...),
                          issue_date=date(...), holder_name=...,  # введённое пользователем, не донорское
                          account=None, account_tail="12345",  # ключ пересчитает движок
                          opening_balance="16.00", operation_count=6,
                          operation_date=date(...), receipt_paths=[...],
                          phone="+7 ...", fill_random=True, output_path=...)
                          # + operation_from_receipt(path) для даты загруженного чека
```

Общее для чеков Рокета: на каждом шаге кнопки «Назад»/«Отмена» (и
`/cancel`); невалидный ввод не продвигает диалог и объясняет формат с
примером; отправитель и последний получатель запоминаются в
`user_data` (`mem_*`, переживают сброс черновика) и предлагаются
кнопкой «Оставить как в прошлый раз»; сводка «Проверь данные» — двумя
блоками ПОЛУЧАТЕЛЬ/ОТПРАВИТЕЛЬ, счёт только последними 5 цифрами
(`…64892`), правка любого поля из сводки с возвратом в сводку; после
суммы — обязательный отдельный блок отправителя (у СБП ФИО → телефон →
счёт; у карты ФИО → счёт так же) и шаг «Время операции»
[Текущее время]/[Изменить время] (`03.11.2026 16:26` или только
`16:26` = сегодня, секунды бот обнуляет — их унаследует движок; в
сводке показывается выбранное время). Ошибка движка — короткое
«Не получилось: …» пользователю, traceback в `logs/bot_errors.log`,
бот не падает и возвращает к сводке для правки.

- **СБП:** имя получателя → телефон (любой формат → `+7…`) → банк
  кнопками, как в чеке (Сбербанк/Т-Банк/ВТБ/Альфа-Банк/Ozon Банк
  (Озон)/Wildberries (Вайлдберриз Банк)/ПСБ/ОТП Банк/МКБ/Совкомбанк/
  Росбанк/Газпромбанк/«Ввести свой») → сумма (пользователь всегда
  пишет сам, только целые рубли, копейки — честный отказ) →
  отправитель → время → сводка → PDF `receipt_rocket.pdf` (имя как у
  настоящей выгрузки Рокета) документом с подписью-сводкой и
  кнопками [Ещё чек]/[Главное меню].
- **По карте:** карта (16 цифр или маска `2200 **** **** 9515`) → банк
  теми же кнопками («Wildberries (в чеке без банка)» = без блока
  банка) → сумма вручную → отправитель → время → сводка → PDF
  `receipt_rocket.pdf`, кнопки те же.
- **Счёт отправителя (чеки):** каждый раз предлагаются три случайных
  счёта кнопками (основа и валюта — как у настоящих счетов Рокета,
  хвост случаен, контрольная 9-я цифра пересчитана по измеренной
  формуле счёта, см. `make_rocket_account` в боте и раздел выписки в
  `banks/rocket/BANK.md`; хвост донора `64892` воспроизводит счёт
  доноров), плюс [Оставить по умолчанию] и [Ввести свой целиком].
- **Клавиатуры и примеры:** кнопки везде рядами по две (слева и
  справа), а не столбиком; примеров с надписью «Подсказка» нет —
  примеры даны моноширинным `<code>`-текстом, который в Telegram
  копируется одним нажатием.
- **Выписка:** период текстом `16.10.2026–23.10.2026` → дата выдачи
  [Сегодня]/[Ввести дату] → ФИО держателя (вводит пользователь) →
  телефон → счёт [Оставить текущий]/[Случайные последние 5 цифр]/
  [Ввести последние 5]/[Ввести целиком] → входящий остаток (копейки
  можно) → число платежей [0][1][3][5][6][Другое (0–10)] → источник
  [Загрузить чек PDF]/[Случайно по настоящим]/[Смешанно]. Чеки
  принимаются PDF по одному («Загружено чеков: N», кнопка [Готово]);
  каждый превращается в операцию движком (`receipt_paths` →
  `operation_from_receipt` внутри движка). Чеков меньше, чем платежей —
  обязательный выбор [Дополнить случайно по настоящим операциям]/
  [Сделать платежей = числу чеков]/[Назад]; дата чека вне периода —
  [Изменить период под чек]/[Отмена]; день случайных операций —
  [День загруженного чека]/[Выбрать дату в периоде]. Сводка (период,
  выдача, держатель, счёт `…xxxxx`, остаток, число платежей и их
  источники) → PDF `Документ.pdf` (имя как у настоящей выписки
  Рокета) с кнопками [Новая выписка]/[Главное меню]. Временные файлы загрузок удаляются после
  успешной генерации и при отмене.

### Как запускать бота

```bash
pip install -r bot/requirements.txt   # если python-telegram-bot ещё нет
BOT_TOKEN=... python3 bot/yandex_bot.py
```

Токен берётся **только** из переменной окружения `BOT_TOKEN`, в коде его
нет и быть не должно. Без `BOT_TOKEN` бот не стартует и печатает, чего
не хватает. Проверка бота без Telegram и сети:

```bash
python3 bot/test_yandex_bot.py   # Яндекс: чеки (режимы, шаблон), выписка (валидаторы, редактор операций, сводка), фейковые движки
python3 banks/yandex/test_statement.py  # движок выписки Яндекса (48 проверок, доноры не тратятся)
python3 bot/test_rocket_bot.py   # Рокет: валидаторы, время, правка из сводки, чеки выписки, фейковые движки
python3 banks/yandex/test_engine.py  # движок Яндекса: round-trip, полная генерация, одноразовость токенов, отказы
python3 test_yandex.py           # патчер Яндекса (регрессия, до движка)
```

Со стороны кода готовность end-to-end есть: бот локально (без
Telegram и сети) проходит весь Яндекс-сценарий в обоих режимах и
выдаёт PDF, движок берёт токен из пула один раз. За владельцем
осталось: загрузить боевой PDF, сгенерированный через бота (в том
числе из режима с PDF), в `@podlinno_bot` (в этом чате в
проверяющие ничего не загружалось) и докладывать свежие настоящие
чеки Яндекса в `banks/yandex/donors/` по мере траты токенов — без
них движок честно остановится на пустом пуле.
